# 从发布到调用模型

::: info 文档信息
版本：v1.0
更新日期：2026-07-08
:::

## 功能概述

本文把运营管理员、模型提供方和模型调用方的模型及AI服务操作串成一条端到端路径：运营管理员先维护元模型、模型来源、模型模板和标签，模型提供方发布单模型或聚合模型并提交审核，审核处理完成后，模型调用方在 **"模型"** 和 **"体验中心"** 查看、体验和调用模型，最后各角色查看调用、用量和收益数据。

| 项目 | 内容 |
| --- | --- |
| 适用角色 | 运营管理员、模型提供方、模型调用方 |
| 推荐前置阅读 | [模型及AI服务快速入门](../../getting-started/)、[元模型](../../operator/settings/meta-models/)、[我的模型](../../user/studio/my-models/)、[我的部署](../../user/studio/my-deployments/) |
| 输出结果 | 一个已配置、审核状态可见，并可在 **"模型"** 中继续检查的模型 |
| 典型用途 | 新模型上架、第三方 Endpoint 接入、聚合模型发布、审核验收和调用排障 |

#### 新手理解

从发布到调用模型像把模型放上货架再完成试用购买：运营管理员先准备元模型、来源和模型模板，模型提供方发布模型，模型调用方在 **"模型"**、**"体验中心"** 和 API 中验证。

## 前提条件

1. 运营管理员具备模型服务设置、应用列表、模型审核和应用审核权限。
2. 模型提供方具备创作空间、发布模型、创建聚合模型和提交审核权限。
3. 模型调用方具备 **"模型"**、**"体验中心"** 和我的调用权限。
4. 发布模型所需的 Endpoint、API Key、模型源 ID、协议和默认参数已准备。连通性结果以页面提供的测试提示或已审批的代表性调用结果为准。
5. 如通过 On-Cloud 快速部署进入链路，当前账号具备 `AI Infra > On-Cloud > 模型服务 > 快速部署` 和 `模型及AI服务 > 创作空间 > 我的部署` 权限。
6. 计费、限流、发布区域和审核流程已明确。
7. 文档和截图中所有密钥、Endpoint 内部地址、请求 ID 和敏感调用参数均已脱敏。

## 主要操作

### 步骤 1：运营管理员维护元模型

1. 进入 `设置 > 元模型`。
2. 如缺少模型作者，先添加模型作者。
3. 点击 **"添加"**，配置模型名称、模型类型、输入模态、输出模态、高级能力、Token 限制、协议和元模型详情。
4. 提交后确认元模型在列表中可见。

**结果校验：**

| 检查项 | 成功表现 | 异常时处理 |
| --- | --- | --- |
| 元模型中出现目标记录 | [元模型](../../operator/settings/meta-models/) 列表出现目标元模型。 | 检查列表筛选条件、目标状态和运营管理员权限 |
| 模型类型、输入输出模态、协议 | 详情页显示模型类型、输入输出模态、协议和上下文上限。 | 打开详情页检查对应字段，再请运营管理员核对配置。 |
| 发布表单显示该元模型 | 重新进入发布表单，检查元模型选择控件。 | 对照元模型状态和发布区域，再请运营管理员检查权限 |

### 步骤 2：运营管理员维护模型来源

1. 进入 `设置 > 模型来源`。
2. 点击 **"添加"**。
3. 填写供应方、区域、请求 URL、请求头、认证信息和来源说明。
4. 提交后确认模型来源在列表中可见。

**结果校验：**

| 检查项 | 成功表现 | 异常时处理 |
| --- | --- | --- |
| 模型来源中出现目标记录 | [模型来源](../../operator/settings/model-source/) 列表出现目标来源。 | 检查列表筛选、来源状态和运营管理员权限 |
| 来源地域、请求 URL 和请求头 | 详情页显示预期的来源地域、请求 URL 和请求头结构。 | 打开详情核对字段，并查看页面提示或请求日志。 |
| 发布表单显示该模型来源 | 重新进入发布表单，检查模型来源选择控件。 | 对照来源地域与发布区域，再请运营管理员检查状态和权限 |

### 步骤 3：运营管理员维护模板和标签

1. 进入 `设置 > 模型模板`。
2. 添加模板，选择模型供应方、作者、元模型、协议、能力和默认参数。
3. 进入 `设置 > 标签`，维护模型和发布流程中需要使用的分类标签。
4. 在列表中确认模板和标签记录及其实际状态。

**结果校验：**

| 检查项 | 成功表现 | 异常时处理 |
| --- | --- | --- |
| 模型模板中出现目标记录 | [模型模板](../../operator/settings/model-templates/) 列表出现目标模板。 | 检查模板状态、关联元模型和运营管理员权限 |
| 标签中出现目标记录 | [标签](../../operator/settings/tags/) 列表出现目标标签。 | 检查标签状态、筛选条件和运营管理员权限 |
| 发布表单显示模板和标签 | 重新进入发布表单，检查对应选择控件。 | 对照对象状态和发布区域，再请运营管理员检查权限 |

### 步骤 4：模型提供方发布单模型

1. 进入 `创作空间 > 我的模型`。
2. 切换到 `我的发布`，点击 **"发布模型"**。
3. 选择发布区域，例如发布到私有区或发布到公有区。
4. 在基本信息中选择元模型和模型来源，填写请求 URL、API Key、模型源 ID、请求头、输入输出模态、高级能力和 Token 限制。
5. 选择支持协议。如果页面提供连通性控件，执行后记录页面实际提示；如果没有该控件，使用已审批的代表性调用路径验证。
6. 填写个性化标识、描述和发布方式。
7. 进入计费配置，选择免费或按 Token 计费，配置阶梯价格、缓存命中、联网搜索和免费额度。
8. 进入限流配置，设置 RPM、TPM 或选择不限制。
9. 核对目标、可见范围、计费、限流和回退方案后，点击 **"仅保存"** 或 **"提交审核"**。

On-Cloud 快速部署分支：

1. 进入 `AI Infra > On-Cloud > 模型服务 > 快速部署`。
2. 按页面流程选择模型、模型版本、资源池、地域、实例规格和副本数，提交前核对资源占用、费用和服务暴露范围。
3. 提交后，部署记录展示在 `模型及AI服务 > 创作空间 > 我的部署` 的 `On-Cloud` 列表。
4. 在 [我的部署](../../user/studio/my-deployments/) 中找到目标部署，点击发布入口并选择发布区域。
5. 选择发布区域后，页面跳转到 [我的模型](../../user/studio/my-models/) 的发布模型页面，继续核对基础信息、计费配置、调用配置和可见范围。
6. 执行最终 **"发布"**、**"提交"** 或 **"保存"** 前，确认目标、可见范围、费用、权限和回退方案。

**结果校验：**

| 检查项 | 成功表现 | 异常时处理 |
| --- | --- | --- |
| 我的模型中出现目标记录 | [我的模型](../../user/studio/my-models/) 列表出现目标模型及实际状态。 | 检查页面提示、发布区域、权限和审核状态。 |
| 我的部署 中 On-Cloud 记录可见 | 通过快速部署提交后，[我的部署](../../user/studio/my-deployments/) 的 `On-Cloud` 列表中目标部署记录可见。 | 未达到时检查快速部署任务状态、账号权限和部署筛选条件 |
| 连通性结果可见（页面提供时） | 连通性控件显示实际成功或错误提示；仅有列表记录不代表连通。 | 检查 Endpoint、请求头、协议和页面原始提示；没有控件时使用已审批的代表性调用路径 |
| 模型记录显示提交状态 | 我的模型或审核页面显示实际记录和状态。 | 检查页面提示、发布区域、权限和审核状态后再重试 |

### 步骤 5：模型提供方创建聚合模型

1. 进入 `创作空间 > 我的模型`。
2. 切换到 `我的聚合`，点击 **"创建聚合模型"**。
3. 选择发布区域。
4. 选择模型类型和模型子类型。
5. 添加 2 个及以上已发布成员模型。
6. 为成员模型配置启用状态、最低成功率、最高并发率、上下文最大长度、输入 Token 成本和输出 Token 成本。
7. 填写个性化标识，选择匹配策略、标签、描述和发布方式。
8. 配置计费方式、计费模式和价格。
9. 核对目标、计费、可见范围和回退方案后，点击 **"仅保存"** 或 **"提交审核"**。

**结果校验：**

| 检查项 | 成功表现 | 异常时处理 |
| --- | --- | --- |
| 我的聚合列表出现目标记录 | [我的模型](../../user/studio/my-models/) 的我的聚合列表出现目标记录及实际状态。 | 检查页面提示、发布区域、成员模型和账号权限。 |
| 成员模型数量不少于 2 个 | 聚合模型表单显示至少 2 个成员模型。 | 检查成员模型的发布状态和选择条件。 |
| 匹配策略、计费配置和发布方式 | 表单或详情页显示已配置的匹配策略、计费配置和发布方式。 | 重新打开详情并逐项核对字段。 |

### 步骤 6：运营管理员处理模型审核

1. 进入 `审批 > 模型审核`。
2. 查看待审核模型列表，按模型名称、状态或提交信息筛选。
3. 打开目标模型详情，检查元模型、来源、Endpoint、协议、计费、限流、标签和发布区域。
4. 根据审核结果执行通过或拒绝。

**结果校验：**

| 检查项 | 成功表现 | 异常时处理 |
| --- | --- | --- |
| 审核记录状态已更新 | [模型审核](../../operator/approvals/model-reviews/) 中目标记录显示处理后的实际状态。 | 检查页面提示、审核意见和当前权限后再重试 |
| 审核通过记录可继续验证 | 审核记录显示 **"审核通过"**；再到发布页或 **"模型"** 单独检查可见状态。 | 对照可见范围、发布状态和发布区域，不把审核通过当成已上架证明 |
| 驳回原因可执行 | 驳回记录显示模型提供方可以处理的审核意见。 | 重新打开详情检查审核意见是否存在；缺失时请运营管理员处理 |

### 步骤 7：模型调用方在模型页面查看模型

1. 进入 `发现 > 模型`。
2. 使用模型名称、模型类型、供应方、标签或搜索框筛选模型。
3. 打开目标模型详情，查看供应方、快速开始、性能和概览。
4. 记录调用前需要确认的协议、价格、上下文、能力和限制。

**结果校验：**

| 检查项 | 成功表现 | 异常时处理 |
| --- | --- | --- |
| 模型页面出现目标记录 | [模型](../../user/discover/models/) 搜索结果出现目标模型。 | 检查审核状态、可见范围、发布状态、标签和账号权限 |
| 模型详情页显示接入信息 | 详情页显示协议、请求信息和快速开始内容。 | 刷新详情页并检查模型可见性；缺少内容时请模型提供方或运营管理员补充 |

### 步骤 8：模型调用方在体验中心试用模型

1. 进入 `体验中心 > 文本对话`，或根据模型类型进入图像生成、视频生成、语音生成。
2. 点击模型选择，选择目标模型。
3. 配置参数，例如 Temperature、Top-P、Max Tokens、Stream 等。
4. 输入测试内容并发起生成。
5. 检查响应内容、耗时、错误信息和模型效果。

**结果校验：**

| 检查项 | 成功表现 | 异常时处理 |
| --- | --- | --- |
| 文本对话中出现目标模型 | [文本对话](../../user/playground/text/) 的模型选择器出现目标模型。 | 检查模型可见性、模态、Personal Key 和账号权限 |
| 响应或错误提示可见 | 响应区域显示生成内容，或页面显示错误提示。 | 记录页面提示和请求 ID，再检查调用日志和模型来源配置 |
| 调用记录可追踪 | 页面提供请求 ID 时，**"调用日志"** 出现对应记录。 | 检查选中模型、时间范围和日志权限，不以页面加载完成推断调用成功 |

### 步骤 9：查看调用、用量和收益

1. 调用方进入 `我的调用 > 概览` 查看整体调用趋势。
2. 调用方进入 `我的调用 > 调用统计` 和 `调用日志` 查看模型维度和单次请求详情。
3. 模型提供方进入 `用量与收益 > 模型收益` 查看收益概览和收益详情。
4. 模型提供方进入 `用量与收益 > 用量明细` 查看消耗明细。
5. 模型提供方进入 `客户调用` 查看客户维度的概览、统计和日志。

**结果校验：**

| --- | --- | --- |
| 我的调用概览显示调用数据 | [我的调用概览](../../user/my-calls/overview/) 显示调用记录或页面空状态提示。 | 检查时间范围、模型、调用状态和日志权限 |

## 踩坑提示

- 元模型、模型来源和模型模板是发布前置配置。缺少其中一项时，发布表单可能不会显示对应选择项。
- 审核通过只代表允许上架，不代表调用方一定具备额度、可见范围和有效 Key。
- 体验中心调通不等于生产接入完成，正式调用前还要核对限流、计费、错误日志和调用凭据。
- Endpoint、API Key、请求头和内部错误日志属于敏感信息，写入文档前必须脱敏。
- On-Cloud 快速部署、选择发布区域和模型发布可能改变真实服务暴露范围。执行最终 **"发布"**、**"提交审核"**、**"保存"** 或 **"创建"** 前，确认目标、费用、可见范围、权限和回退方案。
- **"发布"**、**"提交审核"**、**"审核通过"**、**"驳回"**、**"上架"**、**"创建聚合模型"** 和 **"删除"** 都可能改变平台数据或服务可见性，执行前必须确认影响范围。
- 不记录真实模型 ID、API Key、Endpoint、模型来源凭据、租户信息、用户信息、调用日志或测试参数。

### 失败分支与排查路径

#### 失败分支：模型审核被驳回

下一跳：[模型审核](../../operator/approvals/model-reviews/)

**问题现象：**

模型提供方提交后无法发布，审核记录显示驳回。

**可能原因：**

模型说明、价格、样例、使用边界或授权材料不完整，或模型来源、协议、请求头和安全策略不符合审核要求。

**处理方式：**

1. 阅读审核意见，补齐模型说明、价格、样例、使用边界和授权材料。
2. 核对模型来源、协议、请求头和安全策略。
3. 重新提交前先在受控环境验证来源连通性和输出质量。

#### 失败分支：模型来源连通失败

下一跳：[模型来源](../../operator/settings/model-source/)

**问题现象：**

模型来源或发布页面的连通性控件显示错误，或发布后 **"体验中心"** 无法调用。

**可能原因：**

Endpoint、认证请求头、API Key 或返回格式配置错误，也可能被上游限流、白名单或网络访问策略拦截。

**处理方式：**

1. 检查 Endpoint、认证请求头、API Key 和返回格式。
2. 确认上游服务没有限流、白名单或网络访问限制。
3. 修正页面显示的错误后，使用已审批的代表性调用路径，再关联模板或发布模型。

#### 失败分支：调用返回 401/429/5xx

下一跳：[我的调用日志](../../user/my-calls/call-logs/)

**问题现象：**

调用方通过 API 或体验中心调用失败，返回认证、限流或上游错误。

**可能原因：**

Personal Key、API Key、请求头或模型可见范围不匹配，或触发 QPM、Token、额度、供应方限流和上游服务异常。

**处理方式：**

1. 401 先检查 Personal Key、API Key、请求头和模型可见范围。
2. 429 先检查 QPM、Token 限制、客户额度和供应方限流。
3. 5xx 先查看调用日志中的请求 ID、延迟和模型来源健康状态。

## 结果校验

| 检查项 | 成功表现 | 异常时处理 |
| --- | --- | --- |
| 模型可见 | **"模型"** 页面搜索结果出现目标模型 | 检查审核状态、可见范围、发布状态、标签和账号权限 |
| 可观察的调用结果 | **"体验中心"** 显示生成内容或错误提示 | 记录页面提示和请求 ID，再检查调用日志和模型来源配置 |
| 排障入口 | 审核记录、调用日志或页面提供的来源测试显示实际状态或错误提示 | 打开对应审核或调用日志页面，记录原始提示和请求 ID，再按失败分支排查 |

## 常见问题

#### 模型审核被驳回后怎么处理？

**问题现象：**

模型提交后审核未通过，模型调用方无法在 **"模型"** 使用该模型。

**可能原因：**

模型说明、标签、来源、模板、计费配置、测试结果或安全材料不完整。

**处理方式：**

查看审核意见；补齐模型说明、示例、来源、模板和支持材料；重新提交前先确认敏感信息已脱敏。完成后，审核记录应显示更新后的状态或页面下一步提示。

#### 模型发布成功但调用失败怎么办？

**问题现象：**

模型已经可见，但体验中心或 API 调用返回 401、429、5xx 或超时。

**可能原因：**

API Key、Token、Endpoint、限流策略、模型服务状态或上游模型来源异常。

**处理方式：**

先核对调用凭据、Endpoint 和请求参数；再进入 [我的调用日志](../../user/my-calls/call-logs/) 检查请求 ID 和错误码。请模型提供方或运营管理员检查限流和模型来源配置，等错误提示变化后再重试。

#### 用量和收益数据为什么对不上？

**问题现象：**

调用记录、用量明细、模型收益或客户调用统计中的数量、时间或金额不一致。

**可能原因：**

统计时间范围、模型版本、客户范围、计费规则或数据同步时间不同。

**处理方式：**

统一时间范围、模型版本和客户范围；先看调用日志，再看用量明细和收益统计；确认页面筛选范围一致后再比较数据，仍不一致时保留脱敏线索联系运营管理员。

#### 模型来源列表有记录，但发布表单中没有

**问题现象：**

模型来源列表中有目标记录，但发布表单的来源选择控件中没有该记录。

**可能原因：**

- 来源地域与发布区域不匹配。
- 来源状态或当前账号权限不允许选择。

**处理方式：**

1. 打开 [模型来源](../../operator/settings/model-source/)，检查来源状态、地域和标识。
2. 对照发布表单中的发布区域和供应方。
3. 重新进入发布表单并查看模型来源选择控件。
4. 仍无记录时，请运营管理员修正配置或权限；修正后记录应出现在选择控件中。

#### 调用日志中找不到刚才的请求

**问题现象：**

体验中心或 API 页面显示结果或错误，但 **"调用日志"** 中没有匹配记录。

**可能原因：**

- 时间范围或模型筛选条件排除了该请求。
- 当前角色没有日志权限，或记录已超出保留范围。

**处理方式：**

1. 记录调用时间、所选模型和页面显示的请求 ID。
2. 清空日志筛选条件后重新搜索。
3. 请运营管理员使用脱敏请求 ID 检查日志权限和保留范围。
4. 只有找到匹配日志或明确页面错误时，才继续下一步排查。
