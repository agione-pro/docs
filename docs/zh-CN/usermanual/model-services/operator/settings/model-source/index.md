## 功能概述

| 项目 | 内容 |
| --- | --- |
| 适用角色 | 运营管理员 |
| 导航路径 | **模型及AI服务** > **设置** > **模型来源** |
| 页面路由 | `/modelone/settings/vendor` |
| 管理对象 | 模型来源名称、标识、地域、Base URL、请求头和认证配置 |

#### 新手理解

模型来源用于保存上游模型服务的地址和认证配置。元模型说明模型能做什么；模型来源说明平台从哪里调用服务以及如何认证。

#### 术语表

| 术语 | 说明 |
| --- | --- |
| 模型来源 | 保存上游服务地址和请求头配置的记录。 |
| 地域 | 具有独立 Base URL 的服务位置。 |
| Base URL | 拼接 API Endpoint 前使用的根地址。 |
| Endpoint | 某个 API 操作的具体路径，通常拼接在 Base URL 后。 |
| API密钥地址 | 获取或管理 API Key 的地址，不是模型调用 Endpoint。 |
| 请求头 | 平台调用上游服务时发送的认证或自定义 Header。 |

#### 小白先看

| 场景 | 先做 | 不要直接做 |
| --- | --- | --- |
| 第一次接入新上游服务 | 添加模型来源并填写已审批的上游地址 | 直接创建模板 |
| 模板需要地域 | 完整填写地域标识、地域名称和 Base URL | 只填写模型来源名称 |
| 上游服务要求认证 | 核对默认请求头格式并填写已审批的认证值 | 把 API Key 写入文档或工单 |
| 不清楚模板或发布模型的引用关系 | 打开 **"详情"** 并确认已知引用 | 直接删除模型来源 |

## 前提条件

1. 确认当前账号具备模型来源维护权限。
2. 向上游服务负责人获取地域、Base URL、API密钥地址、API文档地址和请求头要求。
3. 向相关负责人确认网络、证书和白名单要求。
4. 准备经过审批的凭据录入或引用方式。
5. 编辑或删除前，确认使用该模型来源的模板和已发布模型。

## 页面说明

页面用于管理上游模型来源的完整生命周期。不同页面状态承担不同任务：

| 页面状态 | 主要职责 | 离开当前状态前确认 |
| --- | --- | --- |
| 列表 | 定位模型来源，查看名称、标识、地域、Base URL、创建时间和可用操作。 | 已确认目标行和要执行的操作。 |
| 添加表单 | 创建模型来源、地域、地址和请求头配置。 | 必填值已与审批后的上游配置核对。 |
| 详情 | 查看已保存的基本信息、地域信息和请求头预览。 | 已确认保存值和目标记录。 |
| 编辑表单 | 在保持模型源标识不变的前提下维护已审批字段。 | 已重新核对修改字段和影响范围。 |
| 删除弹窗 | 检查下游引用后确认高风险删除。 | 已确认目标和审批，或取消操作。 |

## 主要操作

<!-- main-operation-title-exceptions: 新建,配置,筛选,编辑 -->

按对象生命周期组织：先创建模型源，再为其配置 Endpoint，然后按状态与模态定位目标行；需要核对或维护时分别使用只读详情与配置页。

### 新建模型源

#### 适用场景

- 首次接入一个上游模型服务，需要在模型源接入目录中登记该模型源。
- 已登记的模型源缺少调用地址，需要先创建模型源再配置 Endpoint。

#### 操作步骤

1. 进入 **模型及AI服务** > **设置** > **模型源**。
2. 点击页面右上角的 **"新建模型源"**，打开 **"创建模型源"** 弹窗。
3. 在 `模型源 Code` 中填写上游服务的唯一标识，界面示例为 `unified_model_source`。
4. 在 `模型源显示名称` 下选择 **"简体中文"** 页签，填写中文显示名称。
5. 切换到 **"English"**、**"Español"** 页签，分别填写对应语言的显示名称。
6. 核对填写值后点击 **"创建并配置 Endpoint"**。
7. 不提交时点击 **"取消"**，或点击弹窗右上角的 **"×"**。

弹窗仅有 `模型源 Code` 与 `模型源显示名称` 两项，主按钮文案是 **"创建并配置 Endpoint"** 而不是 **"确定"**。

![创建模型源](./images/model-source-add-public.png)

#### 结果校验

- 在 **模型源** 目录搜索刚登记的 Code，目标行显示该模型源名称。
- 打开 **"详情"**，`模型源 Code` 与填写值一致。
- 顶部 `模型源总数` 统计卡随新增记录计数变化。

#### 注意事项

- `模型源 Code` 与三个语言页签的显示名称均带必填标记。
- 模型源本身不含调用地址，调用地址在 Endpoint 上配置。
- 界面提示逐字为「首个 Endpoint 保存后由后端启用模型源。」

### 配置模型源 Endpoint

#### 适用场景

- 为模型源登记调用地址与协议能力，使该模型源可被下游选择。
- 一个模型源需要多个接入地址或多种区域标签时，继续添加 Endpoint。

#### 操作步骤

1. 在 **模型源** 目录的目标行点击 **"配置"**，进入该模型源的配置页。
2. 在 `Endpoint 管理` 区点击 **"添加 Endpoint"**。
3. 在 `Endpoint 基本信息` 填写 `Endpoint 显示名称`，并按需切换语言页签。
4. 在 `区域标签` 中填写区域标识，界面示例为 `global` 或 `cn-east`。
5. 该地址由模型提供商官方运营时，打开 **"官方 Endpoint"** 开关。
6. 在 `连接地址` 填写必填的 `Base URL`；需要多工作空间动态路由时点击 **"插入 {workspace}"**。
7. 按需填写 `控制台地址` 与 `文档地址`。
8. 在 `协议配置` 点击 **"选择并添加协议"**，选择该 Endpoint 支持的协议。
9. 点击 **"保存 Endpoint"** 提交；离开填写而不提交时点击 **"取消"** 或 **"退出编辑区"**。

`添加 Endpoint` 抽屉分 `Endpoint 基本信息`、`连接地址`、`协议配置` 三段，`Base URL` 右侧有 **"插入 {workspace}"** 按钮。

![添加 Endpoint](./images/model-source-add-endpoint-public.png)

#### 结果校验

- `Endpoint 管理` 区出现新卡片，卡片标题为区域名，右上角显示填写的 `区域标签` 值。
- 卡片内 `Base URL`、`控制台地址`、`文档地址` 与填写值一致，`协议配置` 后的数字与协议条数一致。
- 区顶部提示条逐字为「当前共有 1 个 Endpoint；首个 Endpoint 保存后由后端启用模型源。」，其中数量随实际保存结果变化。

#### 注意事项

- 卡片底部提供 `详情`、`编辑`、`复制` 与 `删除` 四个动作；本轮画面只覆盖列表行 `详情` 打开的只读抽屉，编辑、复制与删除三步的后续界面未采集，操作前确认目标卡片。
- 删除 Endpoint 后模型源的启用状态由后端决定，界面逐字为「Endpoint 独立保存，可新增、编辑、复制或删除至 0 个。」
- 请求头等具体调用参数按协议独立设置，不在本抽屉内填写。
- `{workspace}` 占位符在网关发起调用时替换为实际绑定的工作空间标识。

### 筛选模型源

#### 适用场景

- 目录中模型源较多，需要按启用状态或模态定位目标行。
- 需要确认某个 Base URL 属于哪个模型源。

#### 操作步骤

1. 进入 **模型及AI服务** > **设置** > **模型源**。
2. 在搜索框中输入模型源名称、Code、Endpoint 名称或 Base URL，点击右侧搜索图标。
3. 在 `状态` 组选择 `全部状态`、`已启用` 或 `已停用`。
4. 在 `模态` 组选择 `全部模态`、`文本`、`图像`、`视频`、`音频`、`向量`、`重排` 或 `多模态`。

列表顶部三张统计卡给出 `模型源总数`、`已启用`、`已停用`，其下是状态与模态筛选组。

![模型源筛选区](./images/model-source-filter-public.png)

#### 结果校验

- 列表按 `模型源名称`、`CODE`、`ENDPOINT 与 BASE URL`、`协议能力`、`状态`、`操作` 六列展示。
- 名称下方显示 `N 个 Endpoint`；Endpoint 多于一个的行给出 `查看全部 N 个 Endpoint`。
- 协议能力列显示协议名称与模态标记，未配置时显示 `暂未配置协议`，超出展示数量时显示 `+N`。

#### 注意事项

- 统计卡显示 `已停用` 数量，但本轮画面中的行均为 `已启用`。
- 操作列只有 `配置` 与 `详情` 两个入口。

### 查看模型源详情

#### 适用场景

- 只读核对模型源的 Code、Endpoint 数量与协议配置，不进入编辑。
- 在维护前确认目标记录。

#### 操作步骤

1. 在 **模型源** 目录的目标行点击 **"详情"**。
2. 在 `模型源基本信息` 区核对 `模型源 Code`、`Endpoint 数量` 与右上角状态标记。
3. 在 `Endpoint 管理` 区逐个核对 `Endpoint #1`、`Endpoint #2` 等卡片。
4. 核对每张卡片的区域名、区域标签、只读的 Base URL 输入框，以及 `控制台地址` 与 `文档地址` 链接。
5. 点击 `收起` 或展开 `协议配置`，核对每条协议名称、路径与模态标记。
6. 需要修改时点击 **"前往编辑"**；仅核对时点击 **"关闭"** 或右上角 **"×"**。

详情抽屉副标题逐字为「只读查看模型源、Endpoint 与协议配置」，底部只有 **"关闭"** 与 **"前往编辑"**。

![查看模型源详情](./images/model-source-details-public.png)

#### 结果校验

- 抽屉内不出现保存类按钮，Base URL 以只读输入框展示。
- `Endpoint 数量` 与 `Endpoint 管理` 区右上角计数一致。

#### 注意事项

- `控制台地址` 与 `文档地址` 是外部链接，分享截图前检查链接携带的参数。
- 详情为只读，修改仍需回到配置页并点击 **"保存模型源"**。

### 编辑模型源

#### 适用场景

- 修改模型源在列表与选择控件中的显示名称。
- 维护该模型源下的 Endpoint 与协议配置。

#### 操作步骤

1. 在 **模型源** 目录的目标行点击 **"配置"**。
2. 核对 `模型源基本信息` 中只读的 `模型源 Code`，编辑时保持原值。
3. 在 `模型源显示名称` 的语言页签之间切换，修改对应语言的名称。
4. 需要维护调用地址时，按「配置模型源 Endpoint」新增或修改 Endpoint。
5. 点击 **"保存模型源"** 提交模型源级修改。
6. 点击 **"返回目录"** 回到列表，确认目标行显示新值。

配置页页头显示模型源名称与状态标记，右上角是 **"返回目录"** 与 **"保存模型源"**。

![编辑模型源](./images/model-source-edit-public.png)

#### 结果校验

- 返回目录后，目标行的 `模型源名称` 与 `N 个 Endpoint` 与本次修改一致。
- 重新打开 **"详情"**，`模型源 Code` 未发生变化。

#### 注意事项

- `模型源 Code` 在配置页为只读并带复制图标。
- 模型源级修改与 Endpoint 级保存相互独立，未点击 **"保存模型源"** 时名称修改不生效。

## 参数速查表

下表将表单要求和下游要求分开说明。
本表单中的选填字段，在特定模板或上游服务中仍可能需要填写。

| 字段名称 | 表单要求 | 下游要求 | 字段类型 | 示例 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 英文名称 | 必填 | 所有模型来源都需要 | 多语言文本 | `Example Source` | 英文界面的列表和选择控件显示该名称。 |
| 中文名称 | 选填 | 用户需要中文显示名称时填写 | 多语言文本 | `Example Source` | 中文界面的列表和选择控件可显示该名称。 |
| 模型源标识 | 必填 | 所有模型来源都需要 | 文本 | `example-source` | 填写唯一值，编辑页中为只读。 |
| 地域标识 | 选填 | 模板需要选择地域时必填 | 文本 | `example-region` | 与地域名称和 Base URL 配套填写。 |
| 地域名称 | 选填 | 模板需要选择地域时必填 | 多语言文本 | `Example Region` | 该名称显示在地域选择控件中。 |
| Base URL | 选填 | 已配置地域需要调用上游服务时必填 | URL | `https://api.example.com` | 填写根地址，具体操作路径放在下游 Endpoint 配置中。 |
| API密钥地址 | 选填 | 用户需要 API Key 管理入口时填写 | URL | `https://api.example.com/keys` | 用于管理 API Key，不是模型调用 Endpoint。 |
| API文档地址 | 选填 | 用户需要上游文档入口时填写 | URL | `https://api.example.com/docs` | 填写上游 API 文档地址。 |
| 认证字段名称 | 选填 | 上游服务使用请求头认证时必填 | 文本 | `Authorization` | 页面将 `Authorization` 说明为默认字段名称。 |
| 认证值 | 选填 | 上游服务要求认证时必填 | 文本 | `Bearer <API_KEY>` | 页面将 `Bearer <key>` 说明为默认格式，真实值通过安全方式录入。 |
| 请求头预览 | 系统生成 | 根据已配置请求头生成 | JSON 预览 | `{"Authorization":"Bearer <API_KEY>"}` | 将预览内容与上游规范对照。 |

## 踩坑提示

- 除非上游规范明确要求，不要把具体操作 Endpoint 填入 `Base URL`。
- 模板需要地域时，将地域标识、地域名称和 Base URL 作为一组完整填写。
- 请求头的字段名称、前缀和值格式必须与上游规范一致。
- 修改地址或请求头后，重新打开 **"详情"**，将页面值与已审批配置逐项对照。
- 删除前确认已知的模板和发布模型引用关系，确认弹窗不会显示依赖详情。

| 检查项 | 可观察结果 | 未看到结果时 |

## 常见问题

#### 新增后列表找不到模型来源

**问题现象：**

列表中没有出现新建的名称或标识。

**可能原因：**

- 搜索条件隐藏了记录。
- 表单显示字段校验提示。
- 提交操作未完成。

**处理方式：**

1. 清除搜索条件并刷新列表。
2. 搜索完整的 `模型源标识`。
3. 检查点击 **"确定"** 后的页面提示。

#### 详情与已审批配置不一致

**问题现象：**

详情页显示了不符合预期的地域、地址或请求头结构。

**可能原因：**

- 打开了其他目标行。
- 编辑内容没有提交。
- 已审批值填写到了其他字段。

**处理方式：**

1. 返回列表核对标识。
2. 重新打开 **"详情"**。
3. 将每个可见字段与已审批配置逐项对照。

#### 请求头预览与上游规范不一致

**问题现象：**

`请求头预览` 显示了不符合预期的字段名称、前缀或值格式。

**可能原因：**

- `认证字段名称` 填写错误。
- `认证值` 的前缀或占位符格式错误。
- 多个请求头的组合不正确。

**处理方式：**

1. 对照上游 API 规范核对字段。
2. 只编辑经过审批的请求头值。
3. 重新打开 **"详情"** 并检查 `请求头预览`。

#### 模型模板找不到模型来源

**问题现象：**

`选择供应方` 中没有目标模型来源。

**可能原因：**

- 选择控件中的搜索条件与来源名称不匹配。
- 模板需要地域，但模型来源的地域字段不完整。
- 当前运营管理员账号无法使用目标记录。

**处理方式：**

1. 进入 **模型及AI服务** > **设置** > **模板**。
2. 在左侧 `模型来源` 列表中选择目标来源。
3. 点击 **"添加"**。
4. 在 `供应方信息` 中重新打开 `选择供应方`。
5. 如果 `选择地域` 必填或没有选项，返回模型来源详情并补全地域字段。

#### 下游调用失败

**问题现象：**

模板可以选择模型来源，但下游验证调用失败。

**可能原因：**

- Base URL 或 Endpoint 错误。
- 请求头认证不完整或无效。
- 网络、证书、限流或上游服务策略阻止调用。

**处理方式：**

1. 模型来源页面的配置流程到模板或发布流程中选择来源为止。
2. 根据下游调用流程中显示的错误继续排查。
3. 调用步骤参见[发布模型](/zh-CN/userguide/scenarios/publish-model/)。

#### 删除未完成

**问题现象：**

确认弹窗没有关闭、页面显示错误，或刷新后列表仍显示目标模型来源。

**可能原因：**

- 删除请求没有完成。
- 当前账号缺少所需权限。
- 服务因确认前未显示的原因拒绝了删除。

**处理方式：**

1. 记录页面显示的错误信息。
2. 刷新后搜索目标标识。
3. 向相关负责人确认已知的模板和已发布模型使用情况。
4. 在原因明确前不要重复删除。

## 注意事项

- 列表中可见模型来源，不代表上游服务已经可以调用。
- 真实认证值应保存在经过审批的安全录入系统中。

## 后续操作

下一页操作参见[模型模板](../model-templates/)手册。

**模型来源有地域**

1. 以运营管理员角色进入 **模型及AI服务** > **设置** > **模板**。
2. 在左侧 `模型来源` 列表中选择目标来源。
3. 点击 **"添加"**。
4. 在 `供应方信息` 的 **"选择供应方"** 中选择模型来源。
5. 在 **"选择地域"** 中选择已配置地域。
6. 两个选择控件均显示预期值后，再继续模板流程。

**模型来源没有地域**

1. 打开 `供应方信息` 并检查 **"选择供应方"**。
2. 如果目标来源出现，再检查 **"选择地域"** 的状态。
3. 如果页面要求 **"选择地域"** 或没有选项，停止模板流程。
4. 只有模板负责人确认该流程支持无地域来源时，才可继续。
5. 如果未获确认，返回模型来源页面并添加完整地域配置。

完成模板和发布步骤后，按[发布模型](/zh-CN/userguide/scenarios/publish-model/)执行调用验证。
调用验证不属于模型来源页面操作，应根据该流程显示的响应或错误继续排查。
