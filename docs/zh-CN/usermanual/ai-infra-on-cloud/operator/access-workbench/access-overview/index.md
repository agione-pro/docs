# 接入总览

更新日期：2026-11-12

## 功能概述

| 项目 | 内容 |
| --- | --- |
| 适用角色 | 运营管理员 |
| 导航路径 | AI基础设施 > On-Cloud > 接入工作台 > 接入总览 |
| 页面路由 | `/infrahub/op/workbanch/overview` |
| 管理对象 | 云资源接入、租户使用范围、运行基础与模型上架配置的就绪情况 |

#### 新手理解

接入总览像接入准备检查表：按依赖顺序指出配置缺口，并引导到负责该配置的正式管理页。

#### 术语速查

| 术语 | 说明 |
| --- | --- |
| 目标 | 顶部的任务选择，包括完成模型上架配置、继续接入一朵云和启用高可用。 |
| 阶段 | 接通云资源、开放租户使用、准备运行基础、完成模型上架四个依赖环节。 |
| 当前事实 | 阶段面板中各配置项的现有覆盖情况及待补齐数量。 |
| 模型上架配置 | 元模型关联、云商部署配置、模型来源和 API 配置，不是普通用户创建部署或调用 API。 |

## 前提条件

1. 使用运营管理员身份进入接入总览，并具备对应正式管理页的访问权限。
2. 明确本次任务是完成模型上架配置、继续接入一朵云还是启用高可用，再读取对应目标与阶段提示。
3. 核对上游依赖：云资源接入包含云平台、账号、启用资源池和业务授权；租户使用范围与运行基础分别对应后续阶段。

## 页面说明

页面只负责判断和导航，所有配置仍在正式管理页完成。先看目标与诊断摘要，再按依赖顺序查看阶段，最后通过配置项的检查入口定位正式管理页。

| 区域 | 说明 |
| --- | --- |
| 顶部入口 | 右上角为“接入新云”；目标选择为“完成模型上架配置”“继续接入一朵云”“启用高可用”。目标选择与下方四阶段不是同一组控件。 |
| 诊断摘要 | 展示当前建议及云接入档案、租户配置、模型核心配置的概况；读取数字时同时核对旁边的说明，不把示例数量作为固定要求。 |
| 接通云资源 | 核对云平台、账号、启用资源池和业务授权这一接入链路。 |
| 开放租户使用 | 核对租户可使用的云平台范围。 |
| 准备运行基础 | 核对推理镜像和框架版本准备情况。 |
| 完成模型上架 | 核对元模型、云商、来源与 API 配置；配图中该阶段被选中。 |
| 阶段面板 | 展示“状态”“配置项”“当前事实”“操作”，用于定位缺口和检查入口。 |

![接入总览目标、诊断摘要与四阶段](./images/manual-access-overview.png)

图示为接入总览的目标选择、诊断摘要与四阶段区域；“完成模型上架配置”是顶部目标，“完成模型上架”是当前选中的阶段，右上角另有“接入新云”入口。

## 主要操作

### 读取接入诊断

1. 进入 `AI基础设施 > On-Cloud > 接入工作台 > 接入总览`。
2. 按任务核对顶部目标，阅读诊断摘要中的建议与统计说明。
3. 按“接通云资源 → 开放租户使用 → 准备运行基础 → 完成模型上架”的顺序查看阶段名称、状态及用途，先确认上游依赖再处理当前缺口。
4. 定位当前需要核对的阶段；以下以配图中选中的“完成模型上架”为例。

### 检查模型上架配置

1. 在“完成模型上架”面板，逐行核对“元模型关联”“云商部署配置”“模型来源”“API 配置”。
2. 阅读每行“当前事实”中的覆盖情况与待补齐数量，不只依据状态图标判断。
3. 按待检查内容使用“检查关联”“检查云配置”“检查来源”或“检查 API”入口，配置维护在[模型库](../../deploy-assets/models/)等正式管理页完成，不在总览中修改。
4. 处理配置后，回到总览重新核对相关配置项的当前事实；本页的诊断不能代替正式管理页的配置结果核对。

![完成模型上架阶段的配置检查面板](./images/access-overview-list.png)

图示为“完成模型上架”阶段面板，四行分别提供关联、云配置、来源和 API 的检查入口；底部明确 OP 职责止于模型上架配置，普通用户选择模型、获取推荐方案、创建部署和 API 调用不作为 OP 待办。

## 踩坑提示

- “当前阶段”表示选中的诊断阶段，不等于该阶段每项配置已经完整；面板仍逐行显示当前事实和待补齐数量。
- 云商部署配置、模型来源和 API 配置应结合云平台与资源池核对。面板对 API 配置明确要求同一云平台与资源池，不能只比较模型汇总数。
- 租户概况显示“完整范围未知”时，不应把“已配置”的数量直接解释为全部租户均已授权。

## 常见问题

#### 为什么总览中没有配置表单？

**问题现象：**

面板显示当前事实和检查入口，而不是供填写的配置字段。

**可能原因：**

页面明确说明只负责判断和导航，所有配置在正式管理页完成。

**处理方式：**

使用对应检查入口，进入负责该配置的正式管理页；不要把总览诊断当作配置操作。

#### 顶部目标和下方阶段为何名称不同？

**问题现象：**

顶部显示“完成模型上架配置”，下方阶段显示“完成模型上架”。

**可能原因：**

顶部是目标选择，下方是四阶段检查入口，两者承担不同用途。

**处理方式：**

先确认任务目标，再依据四阶段顺序定位缺口；查看上架配置时核对“完成模型上架”阶段面板。

## 注意事项

- OP 职责止于模型上架配置。普通用户选择模型、获取推荐方案、创建部署和 API 调用属于用户流程，不应列为运营管理员在本页的后续待办。
- 总览中的数字和诊断以当前页面为准；配图中的数量不代表固定配置要求，也不是部署成功或 API 可调用的证明。
- 在正式管理页修改前，确认目标对象、上游依赖和影响范围；不要在任务记录中写入真实凭据、密钥或内部地址。
