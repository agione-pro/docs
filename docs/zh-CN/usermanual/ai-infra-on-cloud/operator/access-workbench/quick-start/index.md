## 功能概述

| 项目 | 内容 |
| --- | --- |
| 适用角色 | 运营管理员 |
| 导航路径 | AI基础设施 > On-Cloud > 接入工作台 > 接入总览 |
| 页面路由 | 旧入口：`/infrahub/op/workbanch/quick`；跳转到 `/infrahub/op/workbanch/overview?stage=cloudAccess` |
| 管理对象 | 旧快速接入入口及云资源接入管理的导航 |

#### 新手理解

当前演示环境的运营端已将快速接入作为[接入总览](../access-overview/)的旧入口，不再是独立的五步检查单。当前页面只负责判断和导航，所有配置仍在正式管理页完成。

#### 术语速查
| 术语 | 说明 |
| --- | --- |
| 旧入口 | 原快速接入路由，现跳转到接入总览。 |
| 阶段 | 接入总览中按依赖顺序组织的四个环节之一。 |
| 正式管理页 | 负责维护对应配置的目标页面。 |

#### 推荐操作顺序

进入当前接入总览，定位所需阶段，再通过导航入口打开负责该配置的正式管理页。完整诊断流程见[接入总览](../access-overview/)。

#### 小白先看

| 场景 | 先做 | 不要直接做 |
| --- | --- | --- |
| 打开旧链接 | 确认已进入接入总览 | 等待独立的五步向导 |
| 接入一朵云 | 使用“接入新云”，核对目标为接入云平台 | 将导航跳转当作已保存云平台配置 |
| 准备变更配置 | 在正式管理页核对依赖、影响范围和目标对象 | 修改未知对象或跳过影响检查 |
| 打开了非预期页面 | 记录当前路由和页面标题 | 反复提交配置或写入真实凭据 |

## 前提条件

1. 使用运营管理员账号，并具备接入总览和相关正式管理页的访问权限。
2. 在正式管理页变更配置前，确认目标平台、租户、业务和资源范围。
3. 按上方当前导航路径进入接入总览；原快速接入链接会跳转到该页面。

## 页面说明

旧路由打开 `/infrahub/op/workbanch/overview?stage=cloudAccess` 的接入总览。当前页面有四个阶段：`接通云资源`、`开放租户使用`、`准备运行基础`、`完成模型上架`；页面只负责判断和导航，不在此保存配置。

## 主要操作

### 打开旧入口

1. 从既有链接打开 `/infrahub/op/workbanch/quick`。
2. 确认进入“接入总览”，路由为 `/infrahub/op/workbanch/overview?stage=cloudAccess`。
3. 按[接入总览](../access-overview/)的当前说明查看诊断，不再等待旧五步检查单。

### 打开接入云平台

1. 在当前接入总览点击 **"接入新云"**。
2. 确认目标页面标题为“接入云平台”；该导航携带 `quickstart=1`、`quickstartStep=platform` 和 `businessId=inference` 查询参数。
3. 配置操作按[接入云平台](../../access-management/cloud-platforms/)说明在正式管理页完成；打开页面不等于已创建或接通云平台。

### 继续查看阶段

1. 使用当前导航入口返回接入总览。
2. 按依赖顺序阅读阶段提示，定位负责对应配置的正式管理页。
3. 在正式管理页核对配置结果；完整检查流程见[接入总览](../access-overview/)。

## 踩坑提示

- 旧入口会跳转到接入总览，不要等待 `5/5`，也不必先寻找旧“查看接入总览”按钮。
- 总览诊断与导航不保存配置；变更前确认范围，并在正式管理页完成配置。
- 导航成功不等于云资源已接通、授权已完成或模型已具备上架条件。
- 示例凭据只使用 `<API_KEY>`、`<PERSONAL_KEY>`、`<ACCESS_KEY_ID>`、`<ACCESS_KEY_SECRET>`、`<BASE_URL>` 和 `<ENDPOINT_PATH>`。

## 常见问题

#### 为什么快速接入会打开接入总览？

**问题现象：**

既有快速接入链接打开的是接入总览，而不是五步检查单。

**可能原因：**

旧路由 `/infrahub/op/workbanch/quick` 现跳转到 `/infrahub/op/workbanch/overview?stage=cloudAccess`。

**处理方式：**

使用当前接入总览菜单，并按[接入总览说明](../access-overview/)查看诊断。

#### 配置应在哪里修改？

**问题现象：**

接入总览提供判断和导航，而不是独立的配置流程。

**可能原因：**

页面明确说明所有配置仍在正式管理页完成。

**处理方式：**

接入云资源时，通过“接入新云”打开[接入云平台](../../access-management/cloud-platforms/)，按负责该配置的正式管理页说明操作；不要把打开页面当作已保存变更。

#### 配图为什么仍是五步示例？

**问题现象：**

保留的旧版示例说明五步流程，当前接入总览则使用四阶段。

**可能原因：**

示例属于旧快速接入流程；旧入口现已跳转到接入总览。

**处理方式：**

按当前页面及[接入总览](../access-overview/)查看阶段，旧 `5/5` 示例不是当前就绪要求。

## 注意事项

- 在正式管理页变更配置前，确认目标平台、租户、业务和资源范围。
- 文档、截图、工单和聊天记录中不得写入真实账号、凭据、内部地址或客户数据。
- 涉及授权、部署、删除、发布、启停或计费的变更，应保留可审计记录并准备恢复方案。

1. 在[接入总览](../access-overview/)继续查看目标、阶段诊断和完整配置检查流程。
