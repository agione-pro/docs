# 场景概览 - 异构卡纳管：算力接入

本场景介绍如何把本地 Kubernetes 集群及其中的 GPU、NPU、XPU 接入 {{DOCS_PRODUCT_NAME_ZH}}，并把硬件能力转换为可调度的资源规格。本场景完成卡型识别、集群接入与所需规格规划。

Kubernetes 是容器编排平台；GPU 为图形处理器，NPU 为神经网络处理器，本教程用 XPU 泛指不同类型的 AI 加速卡。资源 key 是节点上报、作业申请同一类资源所用的名称。

**案例边界：** 下文沿用4张 NPU 的示例。实际型号、数量和规格档位以硬件清单、适配能力与获批需求为准，不要求所有环境具备4张卡或同时建立1/2/4卡规格。

## 适用角色

- 运营管理员
- 集群运维人员


**角色交接：** 集群管理员先提供受控连接材料与硬件清单；运营管理员完成地域、卡型和规格关联；有部署权限的用户再核对规格可选和实际任务分配。交接清单记录集群、地域、卡型与规格，不附真实连接凭据。

## 场景目标

- 平台能够识别目标 NPU 型号和资源 key。
- 集群节点能够上报硬件清单中预期的全部加速卡。
- 用户可以选择已规划且满足实际容量的资源规格。

## 场景流程

**主线：** 创建地域与可用区 → 识别 NPU 卡型 → 接入集群并发现设备 → 建立所需资源档位 → 验证下游可选择

| 阶段 | 核心结果 |
| --- | --- |
| 1. 建立资源边界 | 地域和可用区可供目标集群选择 |
| 2. 识别卡型 | NPU 型号、单卡显存和调度资源 key 口径统一 |
| 3. 接入集群 | 集群和节点可用，硬件清单中的目标设备全部被发现 |
| 4. 建立规格 | 所需资源档位与实际调度拓扑匹配 |
| 5. 验证下游 | 推理模板或测试作业能够选择并申请目标规格 |

## 开始前准备

- 已准备 Kubernetes 集群连接信息和目标地域、可用区。
- 已确认 NPU 厂商、型号、单卡显存及设备插件上报的资源 key。
- 已确认目标加速卡的节点分布，以及所选框架和任务是否支持计划的部署拓扑。
