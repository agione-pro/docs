# 场景概览 - 异构卡纳管：资源计量与监控

本场景介绍如何为租户分配 NPU 配额，并从设备、节点和作业维度检查资源使用。本场景按目标设备清单和获批配额核对资源使用，再结合具体实例记录排查异常。

资源配额是资源数量上限；规格额度是指定规格可用的小时数；credits 是平台记账点数，不能按物理卡数量理解。

**案例边界：** 下文沿用4张 NPU 的示例。实际型号、数量和规格档位以硬件清单、适配能力与获批需求为准，不要求所有环境具备4张卡或同时建立1/2/4卡规格。

## 适用角色

- 运营管理员
- 模型提供方和最终用户（查看自身用量）


**角色交接：** 运营管理员维护用量限制并查看运营级监控；模型提供方和用户核对自身配额、用量及实例记录。需要运营协助时，提供地域、资源或任务标识、时间和账期，由管理员对齐监控与计量范围。

## 场景目标

- 租户具备符合业务需要的 NPU 配额。
- 按实际硬件清单核对目标加速卡的识别与监控数据。
- 能将异常卡、节点和作业关联起来排查。

## 场景流程

**主线：** 配置租户配额 → 运行工作负载 → 关联设备节点与作业 → 核对计量并调整

| 阶段 | 核心结果 |
| --- | --- |
| 1. 配置配额 | 租户获得符合规划的 NPU 使用上限 |
| 2. 运行负载 | 任务按实际所需规格申请并占用资源 |
| 3. 关联监控 | 对齐地域、集群和对象；有时间筛选的页面统一时段，当前快照记录观察时点 |
| 4. 核对调整 | 配额上限、实际占用和账期计量分别明确，差异有依据可追查 |

## 开始前准备

- NPU 已完成纳管，监控采集组件正常上报。
- 已明确租户可用卡数和资源隔离策略。
- 已有至少一个测试作业用于验证计量与监控。

## 完成检查

按下表确认结果；未通过时，返回对应操作页排查后再继续。

| 检查项 | 通过标准 |
| --- | --- |
| 1 | 租户可用配额满足测试或生产要求。 |
| 2 | 已按硬件清单核对目标设备的识别与实际可见监控数据。 |
| 3 | 作业占用、节点水位和设备利用率能够相互对应。 |
| 4 | 租户额度、月度用量和计量明细在同一账期可复核。 |
