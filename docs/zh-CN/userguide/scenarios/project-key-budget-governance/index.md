# 场景概览 - 项目、Key 与预算治理

本场景帮助平台运营方设置展示币种和 Credit 默认兑换倍率，并帮助服务商账号和平台用户创建项目、设置预算和模型白名单，以及为不同用途创建可控、可轮换的调用 Key。Credit 是平台账户的记账额度单位，Key 是程序调用凭据；预算限制消费范围，不代替凭据授权。

## 适用角色

- 平台运营方、模型提供方、平台用户、服务商管理员

## 场景目标

- 项目具备明确用途、预算周期和超预算策略。
- 模型白名单与项目业务范围一致。
- Key 的用途、过期时间、限额和责任人清晰。
- Key 创建后能够完成受控调用，并可在活动或日志中追溯。
- 核对当前平台币种与 Credit 默认兑换倍率，必要变更由运营管理员获批后完成。

## 场景流程

**主线：** 核对已有账务配置（仅必要时变更） → 创建项目 → 配置预算与模型范围 → 创建 Key → 设置限额 → 验证调用与审计

| 阶段 | 核心结果 |
| --- | --- |
| 1. 建立账务基础 | 已有币种和兑换倍率已核对，必要变更已获批 |
| 2. 定义项目 | 项目用途、负责人和成员范围清晰 |
| 3. 治理预算 | 周期预算、预警阈值和超预算策略已保存 |
| 4. 限制访问 | 模型白名单和 Key 范围与项目一致 |
| 5. 验证与审计 | 调用遵守限制，变更记录可追溯 |

## 开始前准备

- 当前账号具备项目和 Key 管理权限。
- 如果由平台运营方执行，确认具备平台设置管理权限，并已确定目标币种和兑换倍率。
- 已明确项目负责人、预算周期、模型范围和超预算策略。
- 已确认使用 Model API Key 还是 System API AK/SK。

## 运营方前置配置

仅首次配置或确需获批变更时，由运营管理员核对平台币种与 Credit 默认兑换倍率；已有配置正确时直接进入项目配置，不必重新保存全局设置。具体操作和 Credits 换算说明统一参阅[项目与 Key 配置流程](./project-key-workflow)，避免在概览中重复维护步骤。

## 推荐阅读顺序

1. 如适用，先完成运营方的币种与 Credit 兑换倍率设置。
2. 创建并检查项目。
3. 配置预算、成员和模型白名单。
4. 创建独立用途的 Key。
5. 设置 Key 限额并验证调用。

## 完成检查

用于生产前，核对项目成本、凭据边界和责任人。

| 检查项 | 通过标准 |
| --- | --- |
| 1 | 币种代码、币种名称、货币符号和 Credit 默认兑换倍率符合当前部署。 |
| 2 | 项目名称、负责人、预算周期和用途清晰。 |
| 3 | 项目预算、预警、超预算策略和模型白名单正确。 |
| 4 | Key 用途、有效期、限额和责任人可追溯。 |
| 5 | 测试调用符合预算、白名单、Key 限额和模型计费规则。 |
