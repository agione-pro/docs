# 场景概览 - 多平台调度：调度策略

本场景帮助运营方在云资源、租户和业务地域完成授权后，配置关联模型、主备路由和健康探测，让后续模型部署按明确的成本、容量和合规边界选择云资源。

主路由是优先使用的服务节点，备路由是在既定规则下接替它的节点；健康探测用于判断节点服务是否可用。

## 适用角色

- 平台运营方、多云资源管理员、部署策略管理员


**角色交接：** 运营或策略负责人配置并核对策略；有部署权限的模型提供方在获准窗口执行测试，回传模型版本、实际节点与事件，由策略负责人复核，不把保存成功当成调度验证完成。

## 场景目标

- 调度策略具备明确关联模型版本、优先级和主路由节点。
- 回退资源池已经授权并具备可用容量。
- 跨地域或跨云回退的时延、成本和合规影响已评估。
- 测试部署能够命中预期资源池或给出明确失败原因。

## 场景流程

**主线：** 检查接入与授权 -> 设计首选和回退 -> 提交策略并核对状态 -> 执行测试部署 -> 核对调度事件与容量

| 阶段 | 核心结果 |
| --- | --- |
| 1. 检查基础 | 云账号、资源池和授权关系完整 |
| 2. 设计策略 | 关联模型、路由优先级和健康探测规则清晰 |
| 3. 验证调度 | 测试部署命中预期资源池或明确失败 |
| 4. 持续治理 | 容量、成本、时延和授权变化被持续复核 |

## 开始前准备

- 已完成[多云资源接入](../on-cloud-resource-access/)。
- 首选和回退资源池已完成租户及业务地域授权。
- 已明确健康探测要求、成本和数据合规边界。
- 已准备一个低风险测试部署和验证时段。

## 推荐阅读顺序

1. 先检查接入总览、资源池和授权关系。
2. 再设计关联模型、主备优先级和健康探测条件。
3. 提交并核对策略状态后执行获批测试部署。
4. 核对实际资源池、部署事件和回退结果。

## 完成检查

核对实际调度结果，而不只确认策略已保存。

| 检查项 | 通过标准 |
| --- | --- |
| 1 | 关联模型及版本、可用部署点与资源授权范围正确。 |
| 2 | 首选和回退资源池均已授权、启用且容量可用。 |
| 3 | 主备优先级与健康探测规则符合规划，成本与合规边界已复核。 |
| 4 | 测试部署命中预期资源池；回退或失败行为符合策略。 |
| 5 | 后续容量和策略复核责任人已明确。 |
