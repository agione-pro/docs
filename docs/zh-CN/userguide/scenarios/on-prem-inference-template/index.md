# 场景概览 - 异构卡纳管：推理模板构建

本场景介绍如何把模型、推理框架、启动参数和资源规格组合成可复用的部署模板。模板维护模型版本、框架版本及适配卡型；具体卡数和规格在部署时按实际需求确认。

推理模板把模型版本与适配的框架版本关联起来；VRAM 指加速卡显存，用于核对模型与运行方案的内存需求。

**案例边界：** 下文沿用4张 NPU 的示例。实际型号、数量和规格档位以硬件清单、适配能力与获批需求为准，不要求所有环境具备4张卡或同时建立1/2/4卡规格。

## 适用角色

- 运营管理员
- 推理平台维护人员


**角色交接：** 运营管理员维护模型、框架和模板关联；模型提供方或其他有部署权限的用户接收可部署组合，在创建实例时确认实际规格、卡数并验证服务。模板维护人员不替用户跳过部署配额或费用核对。

## 场景目标

- 完成模型配置、推理框架和显存测算，创建一个能够选择 NPU 资源规格的推理模板。
- 明确实际部署需要的卡数，并核对模板绑定的适配卡型。
- 用户可以基于模板发起模型部署。

## 场景流程

**主线：** 维护模型配置 → 确认推理框架 → 校验显存测算 → 组合推理模板 → 验证所需卡数与部署参数 → 发布给用户

| 阶段 | 核心结果 |
| --- | --- |
| 1. 准备依赖 | 模型配置、框架、显存因子、镜像、存储和资源规格可用 |
| 2. 组合模板 | 启动命令、环境变量和健康检查形成可复用配置 |
| 3. 验证卡数 | 部署规格与实际卡数及并行参数一致 |
| 4. 发布使用 | 测试部署通过，目标用户能看到并选择模板 |

## 开始前准备

- 已完成 NPU 卡型、集群和资源规格配置，并在资源规格左侧面板维护所需规格指标。
- 已准备模型配置、推理框架、显存测算配置和可用镜像。
- 已确认多卡部署所需的并行参数与驱动环境。
