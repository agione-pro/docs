# 场景概览 - 模型发布审批

本场景介绍运营管理员如何审核模型提供方提交的发布申请，核对模型信息、协议、计费、限流和发布范围。协议约定请求与响应格式，限流控制调用频率或用量上限，两者不是同一检查项。

## 适用角色

- 运营管理员
- 等待审核结果的模型提供方

提供方交出目标模型、提交版本与发布范围；运营管理员处理该版本后交接审核状态与核对依据，提供方再复核生效版本，由目标用户验证访问范围。

## 场景目标

- 审核项能够回溯到发布配置。
- 处理对象、版本和审核结论明确。
- 审批后的模型可见范围符合发布设置。

## 场景流程

**主线：** 定位待审申请 → 核对发布配置 → 作出审核决定 → 验证结果与可见性

| 阶段 | 核心结果 |
| --- | --- |
| 1. 定位申请 | 找到目标模型、提供方和待处理版本 |
| 2. 核对配置 | 模型信息、协议测试、计费、限流和发布范围合规 |
| 3. 审核处理 | 通过或拒绝后重新核对审核状态和审核时间 |
| 4. 验证结果 | 提供方能看到处理结果，通过的模型按预期范围可见 |

## 开始前准备

- 已有待审核的模型发布申请。
- 已明确模型发布规范、计费规则和可见范围。

## 推荐阅读顺序

1. 定位待审核申请
2. 核对模型和协议
3. 核对计费、限流和发布范围
4. 核对版本后通过或拒绝；补充材料按既定渠道交接

## 完成检查

按下表确认结果；未通过时，返回对应操作页排查后再继续。

| 检查项 | 通过标准 |
| --- | --- |
| 1 | 通过或拒绝后，重新查询的审核状态和审核时间符合本次处理。 |
| 2 | 模型提供方在“我的模型”中核对发布状态、生效版本和待生效版本。 |
| 3 | 目标用户按约定范围验证已发布模型的可见性与调用授权；未发布的版本不作为可用版本交付。 |
