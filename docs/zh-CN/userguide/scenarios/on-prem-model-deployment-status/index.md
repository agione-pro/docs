# 场景概览 - 异构卡纳管：模型部署与状态检查

本场景介绍用户如何基于推理模板创建模型实例，并从实例、作业、节点和设备四个层面判断部署是否成功。本场景按实际部署需求核对分配卡数，不以模板名称推断分配结果。

资源规格描述计划申请的资源组合，实际分配需要从实例及任务信息核对；模板或实例名称不能代替分配结果。

**案例边界：** 下文沿用4张 NPU 的示例。实际型号、数量和规格档位以硬件清单、适配能力与获批需求为准，不要求所有环境具备4张卡或同时建立1/2/4卡规格。

## 适用角色

- 模型提供方
- 平台用户
- 参与排障的运营管理员


**角色交接：** 模型提供方与平台用户只管理自己有权操作的实例；出现集群或设备异常时，将实例标识、地域、发生时间及必要事件交给运营管理员，不分享真实密钥或完整敏感请求。

## 场景目标

- 使用 NPU 推理模板创建模型实例。
- 判断实例处于创建、运行、失败还是停止状态。
- 确认实际分配的 NPU 数量与部署时选定的规格一致。

## 场景流程

**主线：** 选择模板与规格 → 创建模型实例 → 检查调度和运行状态 → 验证服务调用

| 阶段 | 核心结果 |
| --- | --- |
| 1. 选择配置 | 模板、卡数、配额、存储和实例参数满足任务要求 |
| 2. 创建实例 | 部署请求进入模型实例列表并可持续跟踪 |
| 3. 检查状态 | 调度、镜像、事件、日志和实际 NPU 占用正常 |
| 4. 验证服务 | 健康检查通过，服务入口完成一次受控调用 |

## 开始前准备

- 已有可用推理模板和足够的租户配额。
- 目标集群有足够的空闲 NPU。
- 已准备模型文件、镜像和启动参数。
